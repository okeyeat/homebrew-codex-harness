# 모델 선택과 작업 방식

정책: `direct-session-2026-09-13`. 공통 기준은 `global/session.md`이며 공개 배포에서는 `POLICY.md`로 제공한다. 이 문서는 필요할 때 읽는 예시다. AGENTS.md에 전문을 복제하지 않는다.

## 선택 순서

1. 사용자 명시 모델·추론을 따른다. 없으면 프로젝트의 명시 선택을 따른다.
2. 둘 다 없고 이미 진행 중이면 관측된 현재 모델·추론으로 직접 계속한다. 작은 하위 작업이나 단계 변경은 모델 전환·워커 생성의 사유가 아니다.
3. 새 작업의 모델을 선택해야 하면 Astra/medium이다. 반복 작업이며 범위·완료 기준이 확정돼 있고 미해결 설계나 복잡한 판단이 없을 때만 Luna/max를 선택한다.
4. 위임은 허용된 상당한 독립 작업 또는 필수 독립 검토에 한한다. 작은 수정마다 워커·검토자를 붙이지 않는다. 독립 검토는 네이티브 서브에이전트를 우선하고, 검토자 모델의 명시 선택이 없으면 Astra/medium이다.
5. 동시 수정에 별도 파일시스템·브랜치가 필요하거나 실행 환경 격리가 필요할 때만 자식 워크스페이스를 만든다. 모델·단계·검토·컨텍스트 크기는 생성 사유가 아니다.

네이티브 기능이 없으면 직접 계속한다. 단, 필수 독립 검토는 직접 검토로 대체하지 않고 이용 가능한 검토 경로가 없음을 보고한다. 별도 터미널을 자동 대체 경로로 만들지 않는다. 지정 모델을 실제로 선택할 수 없으면 제한을 보고하며 적용했다고 추정하지 않는다. 새 호스트를 선택할 때 Codex를 우선하지만 진행 중인 OMP 등 다른 호스트의 세션을 자동 이전하지 않는다.

## 사례

| 상황 | 동작 |
|---|---|
| Astra로 작업 중 버튼 문구 한 줄 수정 | 현재 세션에서 직접 수정한다. Luna 워커를 만들지 않는다. |
| 새 작업이 확정된 규칙으로 파일명을 일괄 정리하는 것 | 명시 모델이 없으면 Luna/max를 선택할 수 있다. 범위와 확인 기준을 전달한다. |
| 원인 불명확한 버그·설계·통합 판단을 새로 시작 | 명시 모델이 없으면 Astra/medium으로 진행한다. |
| 사용자가 독립 리뷰를 요청 | 범위를 제한한 네이티브 리뷰를 사용한다. 선택 가능한 기본 검토 모델은 Astra/medium이다. |
| 서로 다른 변경을 동시에 구현하고 브랜치 충돌 우려가 있음 | 승인된 위임 범위에서 별도 자식 워크스페이스를 사용한다. |
| 컨텍스트가 커짐·호출 횟수가 늘어남 | 현재 세션을 유지한다. 비율·토큰 수·호출 횟수로 점검·인계·새 탭을 요구하지 않는다. |
| 같은 로그를 다시 읽으려는데 입력은 그대로임 | 기존 결과를 사용한다. 관련 변경이나 구체적인 미해결 문제만 재확인한다. |
| 모델·리뷰 기능이 호스트에 없음 | 미지원 상태를 정확히 알린다. 성공·선택 적용을 꾸미거나 자동으로 다른 모델·터미널을 쓰지 않는다. |

## 위임 계약

목표, 담당 경로, 완료 기준, 필요한 증거만 전달한다. 전체 대화 fork는 그 이력이 필요한 구체적 의존성과 이유를 밝힌 경우에만 사용한다. 위임 전 역할·예정 모델/추론·담당 경로를 알리고, 시작 후 실제 모델/추론·세션 ID를 별도로 확인한다. 바뀌지 않은 사실을 매번 다시 조회하지 않는다.

동시 상한은 조정자 1명과 작업자 2명이며 중첩도 포함한다. 경로 소유권을 분리하고 겹치는 수정과 공유 checkout의 Git 변경은 직렬로 수행한다. Orca 격리가 필요한 경우에만 [Orca 절차](orca-sessions.md)를 읽는다.

## 적용 범위

SessionStart는 이 규칙을 전달한다. 모델 자동 전환·탭 생성·쿼터 강제 제어 기능이 아니다. 실행 중인 모델, 런타임 권한과 사용자 지정 작업 경계를 보존한다. 계정 사용량 80% 경고는 알려진 계정 사용량에 대한 규칙이며 컨텍스트 점검 임계치나 자동 하향 조건이 아니다. 과거 OMP adapter의 phase routing은 별도 구현이며 이 Codex 배포가 변경하지 않는다.
