# 모델 선택과 Orca 세션 운영

정책: `role-routing-2026-09-13`. 현재 사용자의 명시적 모델 선택이 우선한다.

| 작업 | 모델 |
|---|---|
| 오케스트레이션, 작업 분해, 위임, 조정, 통합 판단 | Astra/medium |
| 기획, 설계, 아키텍처, 리뷰 | Astra (기존 추론 유지) |
| 어려운 구현, 복잡한 구현, 원인 불명확한 문제 해결 | Astra |
| 명세가 명확한 간단한 구현, 반복 작업, 기계적 수정 | Luna/max |

오케스트레이션은 Astra/medium으로 고정한다. 다른 Astra 역할의 추론 강도는 기존 선택을 유지한다. 알 수 없으면 미확인으로 기록한다.
복잡한 작업의 계약이 확정된 독립 실행은 Luna/max에 배정할 수 있다.
판단과 통합, 리뷰는 Astra가 담당한다. 사용량 80%는 경고 조건이며 자동 하향 조건이 아니다.

## 세션과 워크스페이스

- 컨텍스트 갱신: 같은 워크스페이스의 새 탭, 새 세션. 기존 모델과 추론 유지.
- 조정자의 위임: 부모 작업당 child 워크스페이스 하나. 기존 child ID 재사용.
- 추가 작업자와 후속 세션: 동일 child 내부 탭. 손자 워크스페이스 생성 금지.
- 최대 동시 실행: 조정자 1명, 작업자 2명. 세션 갱신은 동시 작업자 증가가 아니다.
- 공유 checkout에서 경로 소유권을 분리하고 중복 수정과 Git 변경 명령은 직렬 실행한다.
- 인계문 수신과 새 세션 시작 확인 후 기존 세션은 작업을 멈춘다.
- 실패 시 같은 세션 생성 요청을 맹목적으로 반복하지 않고 기존 생성 결과를 조회한다.

## 실행 기록 예시

작업: 로그인 흐름 설계 / 역할: 설계 / 예정 모델: Astra / 실제 모델: 실행 증거 확인 후 기록.
작업: 확정된 폼 구현 / 역할: 구현 / 예정 모델: Luna/max / 위치: 기존 child의 구현 탭.
각 기록은 workspace ID, terminal/session ID, 담당 경로, 검증 기준을 포함한다.

[Orca 실행 절차](orca-sessions.md)를 위임 또는 갱신 직전에 읽는다.
이 정책은 SessionStart가 전달하는 행동 규칙이며 자동 모델 라우터나 자동 탭 제한 장치는 아니다.
