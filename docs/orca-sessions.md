# Orca 격리가 필요한 경우의 위임

이 절차는 공통 정책의 격리 조건을 충족한 승인된 위임에만 적용한다. 일반 작업과 독립 리뷰는 현재 세션·네이티브 서브에이전트가 기본이다. 모델·검토·단계·컨텍스트 크기만으로 Orca 워크스페이스를 만들지 않는다.

## 세션 유지

현재 세션을 계속 사용한다. 컨텍스트 관리 목적의 인계 문서·세션 재개설·대체 탭은 사용자가 명시적으로 요청한 경우에만 수행한다. 비율·토큰 수·모델 호출 횟수로 점검·경고·압축·세션 전환을 요구하지 않는다. 업데이트도 진행 중인 작업을 강제로 재시작하지 않는다.

## 승인된 격리 위임

1. 별도 파일시스템·브랜치 또는 실행 환경이 필요한 이유를 확인하고, 설치된 버전에 맞는 Orca CLI 가이드를 읽는다.
2. 부모 작업의 기존 child ID와 소유권을 확인한다. 없을 때만 기준 branch와 setup 동작을 확인한 후 `orca worktree create --parent-worktree <parent> --name <workstream> --json`으로 하나 만든다.
3. 공통 모델 선택 규칙에 맞는 모델·추론을 지정해 child 내부 터미널에 작업자를 시작한다. 목표·담당 경로·완료 기준·필수 증거만 전달한다. 기본 모델을 실제 모델로 추정하지 않는다.
4. 추가 작업자는 같은 child의 탭을 사용한다. child 안에서 손자 worktree를 만들지 않는다. 조정자 1명과 작업자 최대 2명에 중첩을 포함한다.
5. 같은 파일 수정과 공유 Git index/branch 변경은 직렬로 수행한다. 리뷰 대상 revision을 고정하고 변경되지 않은 검증은 재사용한다.
6. 역할, 예정 및 실제 모델/추론, workspace/terminal ID, 담당 경로와 결과를 기록한다. 시작이 불명확하면 결과를 먼저 조회하고 중복 생성하지 않는다.

현재 확인된 절차는 터미널 탭용이다. native chat 탭·모델 제어 기능은 지원을 확인한 경우에만 사용한다. 이 문서는 자동 실행기가 아니며, 기능 또는 권한이 없으면 그 제한을 정확히 보고한다.
